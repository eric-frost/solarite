No build No Signals Just Simplicity

Solarite is a small JavaScript library for native web components. Just write a class, change your data, call render(). Solarite updates only the DOM that changed.

// Why Solarite

Your data is the state

Nothing to declare or wrap. Change an object or an array, then render.

this.items.push(newItem);
this.render();
Explicit rendering ↗

Two-way form binding

Bind an input to a property and they stay in sync, with no handler to write.

<input value=${[item, 'name']}>
Two-way binding ↗

Regular CSS

Scoped styles with no shadow DOM. Global CSS still reaches inside.

<style>
  :host input { color: navy }
</style>
Scoped styles ↗

Attributes are arguments

A child component’s constructor receives complex data intact.

<user-card user=${user}>

constructor({user}) { … }
Child components ↗

The DOM belongs to you

data-id makes an element a property. Your DOM changes are left alone.

<div data-id="chart"></div>

this.chart.append(canvas);
Element references ↗

Your objects stay plain

No proxies or wrappers. The console and debugger show your real data.

console.log(this.items);
// [{name: 'Apples'}, …]

Works anywhere HTML does

A real custom element, usable from any page or framework.

<my-timer mins="5"></my-timer>

// What Solarite isn’t

A framework

It renders components. Routing, fetching, and stores are yours to choose, or to skip.

Server rendering

Components draw in the browser. Content a search engine must read belongs in your HTML.

A big team

One maintainer, MIT licensed, with a small surface that is easy to read and to fork.

Build your first component.

import h, {Solarite} from 'https://cdn.jsdelivr.net/npm/solarite/dist/Solarite.min.js';
